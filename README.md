# ReviewLens

**From customer feedback to smarter business decisions.**

ReviewLens turns hundreds of raw customer reviews (Google, Zomato, Swiggy, Amazon) into tagged,
prioritised insights and a weekly report a manager can read in five minutes. It understands
English, Tamil and Tanglish.

Stack: Python, LangChain (LCEL), OpenAI, Pydantic, Pandas, Streamlit.

## Quick start (Windows PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env      # then put your OPENAI_API_KEY in .env
streamlit run app.py
```

Click **Or load the sample file** to try it with 240 mixed English / Tamil / Tanglish reviews
(`sample_data/reviews_week40.csv`, regenerate with `python scripts/make_sample_data.py`).

Input CSV columns: `review_id, date, platform, rating, review_text`.

## How it works

```
Upload CSV -> Validate -> Classify (batched) -> Aggregate (pandas) -> Report chain -> Dashboard + CSV
```

| Step | Code | Notes |
|---|---|---|
| Validate | `reviewlens/pipeline.py` | Checks columns, drops empty / duplicate rows and says how many. |
| Classify | `reviewlens/chains.py` | `ChatPromptTemplate \| llm.with_structured_output(ReviewAnalysis)`, run with `chain.batch(max_concurrency=...)`. |
| Retry | `with_validation_retry` | If the output fails Pydantic validation (e.g. a category outside the allowed list) the call is retried up to 3 times. Still failing: the row is kept and marked `needs_review`, the run never crashes. |
| Aggregate | `reviewlens/report.py` | Counts, percentages, top complaints and praise are computed in **pandas**. |
| Report | `reviewlens/report.py` | Map-reduce: per-review summaries are the "map"; ONE report chain reads exact counts plus a capped sample of summaries (the "reduce") and writes the wording and 3 action items. |
| Export | `reviewlens/export.py` | UTF-8 with BOM so Excel shows Tamil correctly; leading `= + - @` are neutralised to block formula injection from review text. |

### Output per review

`sentiment` (positive/neutral/negative), `category` (food_quality, delivery, price, staff,
packaging, app, other), `urgency` (low/medium/high), `language` (English/Tamil/Tanglish/Other),
one-line English `summary`, polite `suggested_reply`, plus `needs_review` and `error`.

`other` was added to the six categories in the brief so that a review that fits none of them
(for example a wrong Amazon product) is not forced into a wrong bucket.

### Design choices worth knowing

- **Numbers are never written by the LLM.** The report prompt forbids counts; the app inserts
  the exact figures from the table, so the report always matches the data.
- **`review_id` is added by code**, not generated by the model, so IDs cannot be mangled.
- **Review text is treated as data.** The prompts tell the model to ignore instructions inside
  reviews, and the report only sees short summaries.
- **The API key lives in `.env`** (git-ignored). There is no key field in the UI.
- Swap models by editing `config.build_llm`; the chains accept any LangChain chat model that
  supports `with_structured_output`.

## Tests

```powershell
pip install -r requirements-dev.txt
pytest
```

The tests need no API key: they cover validation, batching with a failing review, the retry
logic, report statistics, report rendering and the CSV export using fake chains.
